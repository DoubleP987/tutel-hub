# แยกตัวตนบอทและเก็บประวัติเพลง

## แยกบอทปฏิทิน

บอทเพลงใช้ `DISCORD_TOKEN` เหมือนเดิม ถ้าต้องการให้แจ้งเตือนผ่านอีกบอท ให้ใส่ `CALENDAR_DISCORD_TOKEN` ในไฟล์ตั้งค่าส่วนตัวของ homeserver และ Oracle แล้วเริ่มบริการใหม่ ถ้าเว้นว่างจะใช้ตัวเดิม ไม่ต้องใส่ Client ID เพิ่ม เพราะตัวบอทรู้ ID หลังเชื่อมต่อ Discord

โทเคนต้องมาจากหน้า **Bot** ของ Discord Developer Portal ไม่ใช่ OAuth Client Secret ต้องเชิญบอทปฏิทินเข้าแต่ละดิสด้วยสิทธิ์ `bot` และ `applications.commands` พร้อมสิทธิ์ดูช่อง ส่งข้อความ Embed Links และอ่านประวัติข้อความ ไม่จำเป็นต้องให้ Administrator

ระบบแยกบัญชี Discord แต่ยังรันในบริการเดียวกัน แชร์การเลือกโฮสต์และฐานข้อมูล ถ้าปิดบริการหรือปิดบอทผ่าน panel ทั้งสองตัวจะหยุดพร้อมกัน ถ้าโทเคนปฏิทินผิด บอทเพลงยังทำงานได้ แต่ปฏิทินจะไม่ส่ง และมีข้อมูลความพร้อมใน API สถานะ

การตั้งโทเคนแยก **ไม่ได้เปิดระบบกลุ่มให้อัตโนมัติ** `CALENDAR_GROUPS_ENABLED` ยังควบคุมการใช้ระบบเดิม/ระบบกลุ่ม ต้องย้ายช่องอย่างประสานกันก่อนเปิด worker กลุ่ม บอทใหม่ต้องเข้าถึงช่องเดิมให้ได้ ข้อมูลกลุ่มและคีย์ API ไม่จำเป็นต้องเปลี่ยนเพียงเพราะเปลี่ยนบัญชีบอท ข้อความเก่าที่มีปุ่มของบอทเดิมยังเป็นของแอปเดิม บอทใหม่รับปุ่มนั้นแทนไม่ได้

ตอนแก้โค้ดนี้ยังไม่ได้สร้างโทเคนบอทตัวใหม่หรือเปิดใช้งาน การทดสอบบัญชีแยกจริงต้องมีโทเคนและเชิญเข้าเซิร์ฟเวอร์ก่อน การเข้าสู่เว็บไซต์ด้วย Discord OAuth ไม่เปลี่ยน

## ประวัติในห้องเพลง

ระหว่างเล่นใช้แผงเดิม เพิ่มเพลงหรือกดควบคุมจะอัปเดตข้อความนั้น พร้อมชื่อและการกระทำล่าสุด เช่น **DoubleP · เพิ่มเพลง Grayscale Dominator** เก็บในฐานข้อมูลแยกแต่ละดิส ไม่ต้องส่งข้อความถาวรใหม่ทุกครั้ง

เพลงที่เพิ่มผ่านชื่อหรือลิงก์ รวมถึง Playlist เก็บชื่อผู้เพิ่มติดไว้กับเพลงด้วย ถ้าจบเพลง หยุด หรือคิวหมด แผงยังอยู่ ถ้าบอทออกห้อง ปิดบริการ หรือเริ่มระบบใหม่ จะเปลี่ยนแผงเป็นสรุปประวัติแบบไม่มีปุ่ม แสดงเพลงล่าสุดสูงสุด 10 รายการที่แผงติดตามไว้พร้อมคนเพิ่ม โดยไม่ใส่การกระทำล่าสุดในสรุป เมื่อเข้ามาเล่นรอบใหม่จึงสร้างแผงใหม่หนึ่งข้อความ โดยประวัติรอบก่อนยังอยู่

รายการซ้ำ URL/ชื่อเดียวกันรวมเป็นรายการเดียว ไม่ใช่บันทึกครบทุกเพลงทุกครั้ง เพลงสุ่มอัตโนมัติไม่มีชื่อผู้เพิ่มรายเพลง เพลงที่ล้มเหลวหรือสั้นมากอาจไม่อยู่ในสรุป ชื่อเป็นชื่อที่แสดงขณะทำรายการ ข้อความที่ลบไปก่อนอัปเดตนี้กู้คืนไม่ได้ ข้อความตอบส่วนตัวแบบ dismiss ยังหมดเวลาตามเดิม

ดูแผนผังไฟล์และข้อจำกัดทางเทคนิคใน [BOT-IDENTITIES.md](BOT-IDENTITIES.md)

## แก้เพลงแรกไม่เริ่มและข้ามเพลงค้าง

พบเพลงแรกถูก YouTube ปฏิเสธ HTTP 403 แล้วโค้ดเดิมทิ้งเพลงไป ระบบใหม่รอให้แหล่งเสียงพร้อมก่อนเรียกตัวเล่น หากครั้งแรกไม่มีเสียงจะลองดึงใหม่อีกหนึ่งครั้งด้วยรูปแบบ m4a สำรอง จำกัดเวลารอแต่ละแหล่ง 20 วินาที และยกเลิกได้ทันทีเมื่อกดหยุด การโหลดเพลงถัดไปให้เลือก m4a ก่อนเพื่อลดปัญหา Opus ที่พบใน log

อีกกรณีคือเพลงถัดไปติดเงื่อนไขยืนยันอายุ แต่ Smooth รอไม่สิ้นสุด หลังรับคำสั่งข้าม ถ้าเสียงถัดไปพร้อมจะเปลี่ยนแบบ Smooth ทันที หากยังโหลดไม่เสร็จจะยกเลิกการเตรียมเสียง ค่อย ๆ เบาเพลงเดิมแล้วเดินคิวต่อโดยไม่รอ ถ้าเพลงปัจจุบันยังโหลดอยู่จะยกเลิกเพลงนั้น ไม่เริ่มโหลดซ้ำเพราะ Loop เพลงที่เข้าถึงไม่ได้ยังถูกข้ามตามปกติ ไม่หลบการยืนยันอายุ และไม่ได้เพิ่ม cookie ผู้ใช้ การกู้สถานการณ์แบบนี้อาจมีช่วงเงียบเพราะยังไม่มีเสียงเพลงใหม่ ข้อความตอบจึงเปลี่ยนเป็น “กำลังข้ามเพลง…”

หลังหยุด คิวหมด หรือออกห้อง ข้อความจะเหลือประวัติสิ่งที่เล่น ไม่มีการกระทำล่าสุด ส่วนแผงควบคุมที่กำลังใช้งานยังแสดงการกระทำล่าสุดตามเดิม

ทดสอบเฉพาะส่วนเริ่มเสียง Loop Skip Playlist และเก็บแผงประวัติ ผ่าน 31 รายการ เป็นการจำลองกระบวนการและ Discord ไม่ใช่การฟังเสียงจริงในห้อง

ทดสอบผ่าน Brave/Discord วันที่ 10 ตุลาคม 2026: `/join` แล้วเปิด Loop queue และ Smooth เพิ่มเพลงครั้งเดียวเริ่มเล่นได้ ข้ามเมื่อเพลงวนเตรียมพร้อมแล้วเปลี่ยนจริง และข้ามเมื่อยังไม่มีเสียงถัดไปพร้อม เพลงเดิมหยุดและเดินคิวต่อ เพลง YouTube ที่เข้าถึงไม่ได้ล้มเหลวแล้วไปเพลงที่ใช้ได้ แผงยังเป็นข้อความเดิม เมื่อออกห้องเหลือประวัติโดยไม่มีปุ่มหรือการกระทำล่าสุด คืนค่า Loop เป็นปิดหลังทดสอบ ยืนยันจากหน้า Discord และ log ตัวเล่น/การเปลี่ยนเพลง ไม่ได้ยืนยันด้วยการฟังเสียงอิสระ ชื่อเพลงระหว่างโหลดจะไม่ถูกนับเป็นประวัติจนเตรียมเสียงสำเร็จ ประวัติเก่าไม่ได้แก้ย้อนหลัง
